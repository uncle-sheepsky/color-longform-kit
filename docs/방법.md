# 어떻게 만들었나 — 「WHAT YOUR COLOR.」 롱폼의 방법

이 문서는 「무엇을 왜 그렇게 했는지」를 적습니다. 실행 순서는 `README.md` · `AGENTS.md`, 고친 이력은 `제작기.md`.

## 1. 한눈에
- 영상은 네 페이지로 나뉜 HTML 캔버스입니다: `s12`(0~56박) · `s34`(56~136박) · `s56`(136~196박) · `end`(196~240박). 페이지마다 따로 굽고 마지막에 이어 붙입니다(560 + 800 + 600 + 440 = 2,400프레임).
- 페이지는 「프레임 번호 → 그림」 함수 하나입니다. 브라우저를 그 프레임으로 보내 캔버스 픽셀을 PNG 로 받아 ffmpeg 에 넘깁니다.
- 캐릭터는 그리지 않고 **처리**합니다. 사람이 그린 그림을 색 층으로 나눠 두고, 장면마다 층을 다르게 칠하고 겹쳐 「선만 남은 판」「남의 색을 입은 판」「자기 색이 하나만 돌아온 판」「색이 엉뚱한 자리에 앉은 판」「판이 어긋난 망점 판」「실루엣」「원래 그림」 같은 여러 버전을 만듭니다. 이 버전들이 오가는 것이 이야기(색을 찾아가는 캐릭터)입니다.

## 2. 박 지도 — 모든 것의 기준

## 3. 화면을 음악 박에 맞추는 법
- 장면 코드의 모든 시각은 박 단위 상수입니다(예: `if (b >= 131) …`). 프레임 번호 → 박 → 그 박에 해당하는 그림. 음악 쪽도 같은 박 숫자에 음을 놓았습니다(드롭 136 · 박수 208 · 무음 132.5~136 …).
- **박마다 오는 작은 반응**: `kick3(b)` = 박이 바뀔 때마다 한 번 튀었다 잦아드는 값. 원판이 숨 쉬고(반지름 +), 화면이 살짝 펀치 줌하고(박 처음 ¼초), 캐릭터가 눌렸다 튑니다.
- **효과음으로 화면을 따라 치지 않습니다.** 음악이 그 박에 만든 사건이 아니면 화면 사건(글자가 솟는 순간 등)에 소리를 붙이지 않습니다 — 붙였더니 음악과 부딪혔습니다.

## 4. 캐릭터를 층으로 나누는 법(tools/prep.py)
1. **색 묶음**: 그림의 면 안쪽 픽셀(이웃과 색이 거의 같은 픽셀 — 선과 면 사이 섞인 색은 뺌)을 10묶음으로 나눕니다. 시작점을 서로 멀리 고르는 방식이라 넓은 밝은 면이 묶음을 다 먹지 않습니다(이름표 = k-means++ · 시드 고정이라 매번 같음).
2. **역할**: 가장 어두운 묶음 = 선, 그와 아주 가까운 묶음도 선, 밝고 넓은 = 종이, 선과 확실히 다른 어두운 색 = 진한 면, 채도가 높은 색 중 넓이 × 채도가 큰 셋 = k1 · k2 · k3. 같은 색의 밝기 차이(그림자)는 하나로 치고, 색상이 같아도 밝기가 크게 다르면(빨강 · 분홍) 다른 색으로 칩니다.
3. **층**: 그림을 2배로 키워 픽셀마다 가장 가까운 묶음의 역할을 붙이고, 어느 묶음과도 먼 가장자리 픽셀은 가장 가까운 확실한 픽셀을 따르게 한 뒤(선과 면 사이에 다른 색 테가 끼지 않게), 선 옆에 가늘게 남은 다른 색 테는 선으로 돌리고, 다시 줄여 가장자리를 부드럽게 합니다.
4. **작은 표시(tick)**: 다른 키컬러 면 안에 박힌 작은 키컬러 덩어리(볼 안의 빗금 · 단추 등)는 따로 층으로 둡니다. 선만 남은 판에서도 이 표시는 남아 캐릭터다움이 유지됩니다.
5. **기준점**: 눈 = 선 · 진한 면에서 가는 선을 깎아 내고 남은 둥근 점 가운데 위쪽 · 같은 높이 · 비슷한 크기의 한 쌍. 키컬러 조각의 회전 중심 = 그 층의 무게중심. 정적 장면 조각 = 진한 면에서 가장 큰 덩어리(없으면 가장 큰 키컬러 덩어리) · 회전 중심 = 가장 안쪽 점.
6. **그려지는 순서 지도**: 선 층을 덩어리로 나눠 위 → 아래 차례를 주고, 덩어리 안에서는 가장 위 점에서 「선을 따라 잰 거리」를 순서로 삼습니다. 1구간 펜이 이 순서대로 선을 그립니다.

## 5. 움직임
- **젤리**: 캐릭터를 가로 띠 40개로 잘라 띠마다 눌림 · 부풂 · 흔들림을 다르게 그립니다(발치가 고정점). 숨 · 웅크림 · 박수 눌림이 모두 이것.
- **스프링**: 튀었다 잦아드는 값 `imp(t)` 와 넘쳤다 자리 잡는 값 `stp(t)` 를 식으로 바로 계산합니다(앞 프레임 값을 이어 받지 않음 — 그래서 어느 프레임으로 건너뛰어도 같은 값).
- **호응**: 사건(박수 · 착지 · 박)마다 충격을 등록하고, 화면의 다른 요소는 「사건 자리에서의 거리 ÷ 속도」만큼 늦게 그 충격에 스프링으로 반응합니다. 메인(캐릭터)이 움직이면 둘레가 거리 순서대로 따라 움직여 화면 전체가 하나의 흐름이 됩니다.
- **이징**: 손으로 곡선을 짜지 않고 GSAP 의 이징 함수(`power3.out` 등)를 숫자 함수로만 씁니다. 시간 진행은 GSAP 에 맡기지 않습니다(프레임 번호가 시간).
- **장치**: 아이콘 은하(안쪽이 빨리 돌아 팔이 감김 · 앞뒤 깊이로 캐릭터 앞뒤에 나눠 그림) · 탄막 무늬(박마다 아이콘 고리 · 나선) · 수박식 물리(로드할 때 고정 걸음으로 한 번 계산해 표로 읽음) · 리듬게임 노트(남은 박 × 속도 = 높이).

## 6. 같은 입력이면 같은 픽셀(결정론)
규칙과, 그 규칙을 만든 실측:
- 시간은 프레임 번호에서만. 무작위는 정수를 섞는 해시 `hash01(i)`.
- 캔버스 그림자 · blur 를 쓰지 않습니다. 빛 번짐은 파이썬에서 미리 구운 가우시안 그림(glow · streak_glow · cone · 테두리 빛)을 더합니다.
- `imageSmoothingQuality` 는 `'low'` — `'high'` 는 프레임을 건너뛰는 순서에 따라 픽셀 값이 ±1 갈렸습니다.
- 캔버스를 자기 자신에서 읽어 다시 그리지 않습니다 — 앞 프레임이 새어 들었습니다. 화면을 물결로 미는 효과는 띠마다 장면을 처음부터 다시 그립니다.
- 매 프레임 붓 상태를 처음으로 돌립니다(`lineWidth` 에 0 을 넣으면 무시돼 앞 프레임 값이 남았습니다).
- 기울인 종이 바탕은 실행마다 다르게 그려졌습니다 → 바탕은 수평으로 두고 캐릭터만 기울입니다.
- **판정**: 페이지 안에서 캔버스 원시 픽셀의 해시를 잽니다(`window.__hash`). 같은 페이지를 정순으로 한 번(영상과 함께) · 역순으로 한 번 그려 모든 프레임 해시가 같으면 통과. mp4 파일 해시는 인코더 사정으로 달라질 수 있어 화면 판정에 쓰지 않습니다.
- 래스터는 소프트웨어(SwiftShader) · 글꼴 · 색 프로필 · 하위 픽셀 위치를 고정하는 브라우저 옵션을 씁니다(`render.mjs` 의 FLAGS). 글꼴은 영상에서 직접 그리지 않고 미리 그림으로 굽거나 사각형 픽셀 글꼴로 그립니다.

## 7. 번쩍임
- 측정: 64×36 회색으로 줄인 화면 평균 밝기가 이웃 프레임 사이 20(0~255) 넘게 변하면 「점프」, 반대 방향 점프 둘 = 번쩍임 1번, 어느 1초 창에서도 3번 이하.
- 장면에서 피한 방법: 박마다 「동그라미로 열림」을 쓰면 첫 프레임에 화면 전체가 색이었다가 다음 프레임 어둠으로 바뀌어 번쩍임이 됐습니다 → 처음부터 넓게 열린 원에서 시작. ½박 샷과 그 바로 앞 샷은 전신 구도만(밝은 얼굴 · 글자 구도와 번갈면 1초 3번에 닿음). 밝음 ↔ 어둠이 뒤집히는 몰아치기는 한 박(1/3초)에 한 번만.

## 8. 음량
- 완성 곡: 통합 −14 LUFS · 트루피크 ≤ −1.5(영상에 AAC 로 넣은 뒤 검사는 −14 ± 0.5 · ≤ −1.0).
- 구간 크기를 손으로 키우지 않습니다: 구간마다 「전체 대비 몇 dB」 목표(아치)를 정해 두고, 실제로 잰 크기와의 차이만큼 자동 배율을 곱합니다(`TARGET` · `auto_secg`). 가장 큰 곳 = 드롭 · 박수 정점, 가장 작은 곳 = 처음 · 끝.
- 정적 구간(132.5~136박)은 리버브 꼬리까지 통째로 0. 들어오는 쪽은 4ms 에 걸쳐 닫습니다(뚝 소리 방지).

## 9. 음악 규칙(만들며 정한 것)
- 세계를 먼저 정함: 「종이 미술실의 작은 실내 악단」 — 실제 악기 녹음만, 합성 소리는 신호 두 음과 박수뿐.
- 색 하나 = 악기 하나: k1 = 약음 트럼펫 · k2 = 바순 · k3 = 플루트 · 남의 색 = 솔로 바이올린.
- 주선율 · 대선율 · 반주를 앞 · 가운데 · 뒤로 나눔: **대선율은 주선율이 화음음으로 머물 때만** 16분 늦게, 3도 이상 아래에서, 2도 · 7도 · 증4도로 겹치지 않게. 같은 박에 같이 치지 않음. (`counter()` · 보고서 `clash`)
- **스윙이면 음 길이도 스윙 위치로**: 걸음이 스윙(8분 앞 58%)인데 음 길이를 곧은 박으로 세면 박 위 8분이 다음 음보다 일찍 끝나 톡톡 끊깁니다 → 다음 음 시작까지 이어 세고, 쉼 없이 이어지면 40ms 겹쳐 이음.
- 주선율 ≤ MIDI 76 · 흔드는 타악(셰이커 · 방울)을 깔지 않음 · 화음 진행은 이 채널의 다른 곡과 겹치지 않게 고름(안달루시아 하강 · B 도리아 드론 · 나폴리 화음 · 단조 → 장조 도착).

## 10. 이 키트로 옮긴 방법과 확인
- 원래 작업 페이지에는 반려된 옛 판의 함수가 많이 남아 있었습니다. 키트에는 최종 영상을 실제로 그리는 코드만 옮기고, 캐릭터 고유 값(색 · 동작 이름 · 눈 위치 · 조각 위치 · 끝 화면 부품)을 전부 `build/` 자료에서 읽게 바꿨습니다.
- 확인 1: 원래 캐릭터의 층과 부품을 키트 형식으로 넣고 네 페이지를 그렸더니 **2,400프레임 모두 원본과 픽셀 해시가 같았습니다**(옮기며 그림이 바뀌지 않았다는 뜻).
- 확인 2: `music/build_music.py` 로 다시 만든 곡의 WAV 가 원본 곡과 **바이트까지 같았습니다**(SHA256). 최종 영상 속 소리와도 지연 0 · 상관 0.9999(AAC 차이만).
- 확인 3: 빈 폴더에 이 저장소를 새로 받아(새 Python 3.10 가상환경 · `npm install`) 시험 캐릭터로 처음부터 mp4 까지 돌려 검사를 모두 통과했습니다(설치 약 1분 · `make.py all` 약 14분). 그림 1장 + 글꼴 파일 경로도 네 구간 모든 프레임을 그려 봤습니다.
- 덤: 같은 컴퓨터에서 Pillow 판이 다른 두 가상환경(12.2 · 12.3)으로 준비물을 만들어 그려도 1~6구간 프레임 해시가 같았습니다(끝 구간은 그 사이 제목 색 규칙을 바꿔 비교하지 못함).
- 확인 안 됨: 다른 컴퓨터 · 다른 Chromium 판에서 같은 픽셀이 나오는지.
