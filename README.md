# color-longform-kit — 내 캐릭터로 만드는 80초 롱폼 템플릿

**원하는 캐릭터 그림을 넣으면, 그 캐릭터의 색으로 80초 가로 영상(1920×1080 · 30fps · 음악 포함)을 만들어 주는 템플릿입니다.**
유튜브 채널 「아낌없이 주는 두루」의 롱폼 「WHAT YOUR COLOR.」를 만든 코드와 방법 그대로이고, 캐릭터 자리를 여러분의 그림으로 채우게 열어 두었습니다.
같은 이야기의 20초 세로 숏폼 판은 [color-short-kit](https://github.com/uncle-sheepsky/color-short-kit) 에 있습니다.

- 이 키트로 만든 원본 영상: 롱폼 https://youtu.be/2T3t7NSwQis · 롱폼에서 잘라 낸 세로 숏폼 https://youtu.be/Kh3IdNJEvVM

## 설치 없이 브라우저에서 — 그림 1장으로
**[웹 페이지](https://uncle-sheepsky.github.io/color-longform-kit/web/)** 에 투명 바탕 PNG 한 장을 넣으면, 색을 뽑아 보여 주고(고칠 수 있음) 같은 움직임 · 같은 음악의 영상을 브라우저 안에서 바로 구워 줍니다. Python · ffmpeg · AI 도구가 필요 없고, 그림은 서버로 올라가지 않습니다.
- 내려받는 형식: 16:9 가로(80초) · 9:16 세로(34.7초 · 릴스 · 틱톡 · 쇼츠) · 4:5 세로(34.7초 · 인스타 피드)
- Chrome · Edge 최신판 권장 · 쓰는 법 · 한계 · 로컬에서 여는 법은 [`web/README.md`](web/README.md)
- 동작을 여러 개 쓰거나 형식 검사 보고서까지 받으려면 아래 Python 판을 쓰세요.

AI(Claude · Codex 등)를 쓴다면 이 저장소를 그대로 주고 아래 프롬프트를 붙여 넣으세요. AI 가 따라갈 단계와 확인 방법은 [`AGENTS.md`](AGENTS.md) 에 있습니다.

막히는 곳이 있으면 고치기 전에 무엇이 왜 막혔는지 먼저 알려 줘. 끝나면 build/check.png 와 spot 시트를 보여 줘.

내 캐릭터로:
```text

- 내 캐릭터 그림: (폴더 경로) — 투명 바탕 PNG · 동작 폴더 (몇 개 / 1장뿐)
- 이름: (이름) · 끝 제목: (예: 이름 / IN COLOR)
- 글꼴: (파일 경로 · 없으면 픽셀 글꼴)
- 음악: 들어 있는 곡 그대로
정할 게 생기면(동작 배정 · 부위 이름 · 색이 틀렸을 때) 기본값으로 채우지 말고 나한테 물어봐.
prep 뒤 build/check.png, spot 뒤 시트를 보여 주고 내가 괜찮다고 하면 전체를 구워.
마지막엔 gates/report.json 을 그대로 보여 주고, 화면이 괜찮은지는 내가 직접 보고 판정할게.
```

## 무엇이 만들어지나
선만 남은 캐릭터가 **자기 색을 하나씩 찾아가는** 80초(♩180 · 240박).

| 구간 | 시간 | 화면 |
|---|---|---|
| 1 선화 | 0:00~0:08 | 어둠 속 펜 빛이 선을 따라 캐릭터를 그림 → 종이색이 참 → 원래 색이 2프레임 비쳤다 사라짐 |
| 2 남의 색 | 0:08~0:18.7 | 2박마다 남의 색을 입어 봄(원판 · 발치부터 차오름) · 연한 코드 글자 · 리듬게임 노트 |
| 3 자기 색 | 0:18.7~0:36.7 | 자기 색이 하나씩(k1 → k2 → k3) · 구도가 박마다(전신 · 거대 글자 · 화면 속 화면 · 얼굴 · 격자 · 망점 …) · 떨어져 쌓이는 아이콘 |
| 4 엇나간 자리 → 자리 찾기 → 정적 | 0:36.7~0:45.3 | 색이 엉뚱한 부위에 앉음 · 색 조각이 제자리를 찾아 딸깍 · 1.2초 정적 |
| 5 드롭 → 원판 속 세계 | 0:45.3~0:57.3 | 원래 색이 한꺼번에 · 아이콘 은하 · 원판 속 테트리스 → 블랙홀 |
| 6 빛 | 0:57.3~1:05.3 | 실루엣 캐릭터 · 빛 입자 은하 · 입자가 해로 빨려 들어 화면이 주황으로 |
| 7~8 끝 화면 | 1:05.3~1:20 | 끝 화면(썸네일 구도)이 조각조각 만들어짐 · 박수 · 제목 글자가 한 글자씩 · 멈춤 |

- 색은 여러분 그림에서 자동으로 뽑습니다(가장 어두운 = 선 · 밝고 넓은 = 종이 · 진한 면 · 채도 높은 색 셋 = 하나씩 돌아오는 색 k1 · k2 · k3).
- 음악 `music/color_longform.wav` 는 이 구조에 맞춰 만든 곡입니다(실제 악기 샘플 VSCO 2 Community Edition · CC0 · 만든 코드 `music/build_music.py`). 화면의 사건이 이 곡의 박에 맞춰져 있습니다.
- 모든 화면은 프레임 번호의 순수 함수입니다 — 같은 입력이면 같은 픽셀(정순 · 역순으로 그려 해시를 대조합니다).

## 준비물
- Node.js 18+ · Python 3.10+ · ffmpeg(명령줄에서 `ffmpeg` · `ffprobe` 가 되면 됨)
- `npm install` → 처음 한 번 `npx playwright install chromium`
- `pip install -r requirements.txt` (numpy · pillow · scipy · pyloudnorm)

## 먼저 시험 캐릭터로 한 바퀴
코드로 그린 시험 캐릭터 「MOMO」로 처음부터 끝까지 돌려 보면 환경이 맞는지 바로 압니다.
```bash
python examples/make_sample_character.py
python make.py all --character examples/sample
```
끝나면 `out/color_longform.mp4` 와 검사 보고서 `gates/report.json`(`all_pass: true`) 이 나옵니다. 시간은 컴퓨터에 따라 다르지만 렌더가 대부분입니다(이 키트를 만든 컴퓨터에서 설치 약 1분 + `make.py all` 약 14분).

## 내 캐릭터로 만드는 순서
1. **캐릭터 넣기** — `character/<동작 이름>/00.png, 01.png …`(투명 바탕 PNG). **그림 1장만 있어도 됩니다**(`character/main/00.png`). 동작을 여러 개 넣으면 장면마다 다른 동작이 나옵니다 — 어느 장면에 어떤 동작이 쓰이는지는 [`character/README.md`](character/README.md).
2. **이름 · 제목** — `config.json` 의 `name`(거대 글자 · 코드 글자에 쓰임) · `title`(끝 화면 제목 줄 · `{name}` 자리에 이름) · `part_names`(코드 글자에 나오는 부위 이름).
3. **글꼴(선택)** — `fonts/` 에 .ttf/.otf 하나(SIL OFL 같은 재배포 가능한 글꼴). 없으면 픽셀 글꼴로 그립니다.
4. 실행
```bash
python make.py prep
python make.py spot
python make.py render
python make.py finish
```
- `prep` 뒤 **`build/check.png`** 를 꼭 보세요: 뽑힌 색 · 층 나눔 · 눈 위치 · 정적 장면에 쓸 진한 면 조각 · 끝 화면 배치가 한 장에 있습니다.
- `spot` 뒤 `spot/<구간>_sheet.jpg` 로 몇 장면을 먼저 확인한 다음 전체를 굽는 걸 권합니다.
- `finish` 가 결정론(정순 = 역순) · 프레임 수(2400) · 번쩍임(1초 3번 이하) · 음량(−14 LUFS · 트루피크 −1 이하)을 재고 `out/color_longform.mp4` 를 만듭니다.
- (선택) `python make.py short` — 롱폼의 드롭 ~ 끝(34.7초)을 세로 숏폼(1080×1920 · 4:5 칸 + 위아래 여백)으로. 4:5 창이 음악 박마다 볼 거리 쪽으로 건너가며 움직입니다 → `out/color_longform_short.mp4`.

## 바꿔 보기
| 바꾸고 싶은 것 | 어디서 |
|---|---|
| 뽑힌 색이 마음에 안 듦 | `config.json` 에 `"palette": {"k1": "#E83437"}` — 쓸 수 있는 이름 `ink` · `paper` · `deep` · `k1` · `k2` · `k3` (층 나눔은 그대로, 칠하는 색만 바뀜) |
| 색이 돌아오는 순서 | `"key_order": [2, 0, 1]` (지금 k3 를 첫째로 …) |
| 눈 위치 · 박수 자리 등이 어긋남 | `"anchors": {"eye_zoom": [900, 520], "hands": [1500, 600]}` — 값의 뜻은 [`AGENTS.md`](AGENTS.md) |
| 남의 색 8가지 · 그 이름 | `"other_colors": ["#38836D", …]` · `"other_names": ["MINT", …]` |
| 끝 화면 색 | `"end": {"sun": "#FD9702", "wave": "#E02B2C", "cream": "#FDDCA6"}` |
| 장면 순서 · 구도 · 박 | `scenes/*.html` (값 표가 각 파일 위쪽 주석에 설명돼 있음) · 아이콘 · 장치 = `scenes/devices.js` |
| 음악 | `music/build_music.py` (박 지도를 바꾸면 화면도 같이 바꿔야 함 — [`docs/방법.md`](docs/방법.md)) |

어떻게 만들었는지(박 지도 · 화면을 음악 박에 맞추는 법 · 결정론 · 해시 대조 · 음량 · 대선율 규칙)는 [`docs/방법.md`](docs/방법.md), 만들면서 무엇을 바꿨는지는 [`docs/제작기.md`](docs/제작기.md).

## 확인된 것 · 확인 안 된 것
- 확인: 이 저장소를 빈 폴더에 새로 받아(새 Python 3.10 가상환경 · `npm install`) 시험 캐릭터로 처음부터 mp4 까지(검사 모두 통과) · 그림 1장 + 글꼴 파일 경로도 네 구간 모든 프레임이 그려짐 · 원본 롱폼을 만든 장면 코드와 같은 그림이 나오는지(원본 캐릭터 층을 넣었을 때 2,400프레임 픽셀 해시 전부 같음 · 음악 WAV 바이트까지 같음).
- 확인 안 됨: **다른 컴퓨터(다른 OS · 다른 Chromium)에서 같은 픽셀이 나오는지.** 한 컴퓨터 안에서는 몇 번을 그려도 같습니다. 번쩍임 검사는 화면 평균 밝기만 보는 단순 측정입니다(작은 영역 · 빨강 번쩍임은 따로 보지 않음).
- 그림이 내 캐릭터답게 보이는지, 음악과 화면이 맞는지는 형식 검사가 판정하지 못합니다 — 소리를 켜고 끝까지 직접 보세요.
