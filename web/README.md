# web/ — 설치 없이 브라우저에서 만들기

이 폴더는 **원하는 캐릭터를 넣어 만드는 템플릿**을 웹 페이지 하나로 쓰게 해 줍니다. Python · Node · ffmpeg · AI 도구 없이, 투명 바탕 PNG 한 장으로 같은 움직임 · 같은 음악의 「WHAT YOUR COLOR.」 영상을 만듭니다.

- 주소: https://uncle-sheepsky.github.io/color-longform-kit/web/
- 넣은 그림은 브라우저 안에서만 쓰이고 서버로 올라가지 않습니다(정적 페이지 · 서버 코드 없음).

## 쓰는 법
1. **그림 넣기**: 투명 바탕 PNG(또는 WEBP) 한 장을 고르거나 끌어다 놓습니다. 먼저 해 보려면 예시 「두루」 · 「멜론」을 누릅니다(채널 그림 · 시험용 · 아래 「예시 그림」 참고). 편집 화면에서도 새 그림을 끌어다 놓으면 바로 바뀝니다.
2. **그림과 색**: 뽑힌 색(선 · 종이 · 진한 면 · 색 1~3)이 칸으로 나옵니다. 칸을 누르거나 마우스를 올리면 그 색이 그림의 어디인지 밝혀 보여 줍니다.
   - 네모를 누르면 칠하는 색을 바꿀 수 있고, 「⇅ 순서 바꾸기」로 색이 돌아오는 순서를 바꿉니다.
   - 빨간 원이 두 눈 위에 없으면 「눈 다시 찍기」를 누르고 그림에서 왼쪽 눈 · 오른쪽 눈을 차례로 누릅니다.
   - 바꾼 내용은 잠깐 뒤 미리 보기에 바로 들어갑니다(따로 누를 단추 없음). 「처음 뽑힌 대로」는 처음 상태로 되돌립니다.
3. **이름과 끝 제목**: 이름 · 끝 제목 두 줄 · 부위 이름(영문)을 적고, 한글 제목이면 「제목 글꼴 넣기」로 글꼴 파일(.ttf/.otf)을 넣습니다.
4. **미리 보기**(왼쪽): 막대를 끌거나 아래 구간 막대를 눌러 장면을 봅니다. 주황 괄호는 세로 영상이 시작하는 자리입니다. 재생 단추는 확인용(컴퓨터에 따라 끊길 수 있음).
5. **영상 만들기**: 형식 칸을 고르고 「영상 만들기」 → 굽는 동안 지금 그리는 장면과 남은 시간이 보이고, 다 되면 각 영상 옆 「내려받기」.
   - 16:9 가로 1920×1080 · 80초(유튜브 롱폼)
   - 9:16 세로 1080×1920 · 34.7초(릴스 · 틱톡 · 쇼츠) — 드롭부터 끝까지 · 4:5 칸 + 위아래 어두운 여백 · 창이 음악 박마다 볼 거리로 이동
   - 4:5 세로 1080×1350 · 34.7초(인스타 피드) — 위와 같은 창, 여백 없이
   - 올릴 때 쓸 설명 문구(원본 영상 · 템플릿 링크)를 복사할 수 있습니다.

걸리는 시간(이 키트를 만든 컴퓨터 · Chrome 계열): 그림 분석 약 5초 · 16:9 + 9:16 굽기 약 40초.

## 브라우저
- **Chrome · Edge 최신판 권장** — WebCodecs 로 프레임마다 그려 H.264 + AAC MP4 로 굽습니다(빠르고 끊김 없음). H.264 를 못 쓰면 VP9 · AV1, AAC 를 못 쓰면 Opus 로 바꿔 굽습니다.
- WebCodecs 가 없는 브라우저는 **실시간 녹화**(MediaRecorder)로 만듭니다: 영상 길이만큼 걸리고, 그리기가 느린 컴퓨터에서는 프레임이 몇 장 빠질 수 있습니다(빠진 수를 화면에 표시). 녹화 중에는 탭을 앞에 두세요. 시험하려면 주소 끝에 `?mode=realtime`.
- 인터넷 연결이 필요합니다: GSAP(이징 함수 · `gsap@3.15.0`)과 mp4-muxer(`mp4-muxer@5.2.2` · MIT)를 jsDelivr CDN 에서 불러옵니다.

## 어떻게 돌아가나
| 파일 | 하는 일 |
|---|---|
| `prep.js` | `tools/prep.py` 를 옮긴 것 — 색 묶음(k-means++ · 결정론 시드 · 10묶음 · 채도 0.3 이상 · 색상 25° 안은 하나만) → 층 나눔(sil · ink · deep · k1~k3 · tick) · 눈 · 그림 순서 지도 · 테두리 빛 · 끝 화면 부품 · `PAL` · `GEO` · `KIT` · `MK` |
| `scenes.js` | `scenes/*.html` 네 페이지를 **고치지 않고** iframe 에서 돌림. `build/kit.js` · `masks.js` 는 같은 내용의 인라인 스크립트로, `build/` 그림은 메모리의 캔버스로 건넴(PNG 로 다시 굽지 않음) |
| `render.js` | 프레임마다 시크 → WebCodecs 인코딩 → `music/color_longform.wav` 를 AAC 로 넣어 MP4 로 묶음. 세로판은 `tools/make_short.py` 의 창 이동 계획을 그대로 옮김 |
| `app.js` · `index.html` | 화면(그림 넣기 · 색 고치기 · 미리 보기 · 굽기) |
| `duru.png` | 예시 「두루」의 그림(채널 승인 원화 그대로 · CC0 아님 · 아래 「예시 그림」) |
| `melon.png` | 예시 「멜론」의 그림(CC0 아님 · 아래 「예시 그림」) · 몸 색 · 눈 자리는 `app.js` 에 미리 맞춘 값 |

장면 코드 · 음악 · 박 지도는 Python 판과 같은 파일을 씁니다(복사본 없음). 장면을 고치면 웹 판에도 그대로 들어갑니다.

## 예시 그림
`duru.png` 는 유튜브 채널 「아낌없이 주는 두루」의 캐릭터 두루이고, `melon.png` 는 같은 채널의 멜론 그림입니다. 이 저장소에서 이 두 파일만 CC0 가 아닙니다. 이 페이지를 시험해 보는 데만 쓸 수 있고, 다시 배포하거나 상업적으로 쓸 수 없습니다(그 그림으로 만든 영상도 같음). 두 그림 모두 GPT 로 만든 그림입니다. 자세히는 저장소 루트의 [`NOTICE`](../NOTICE). 코드 · 음악과 Python 판의 시험 캐릭터 MOMO(`examples/`)는 CC0 입니다.

## Python 판과 다른 점
- 그림은 **한 장**(동작 하나)만 받습니다 — 모든 장면이 이 그림을 돌려 씁니다. 동작을 여러 개 쓰려면 Python 판(`character/<동작>/`).
- 색 묶음의 무작위 시드 계열이 다르고(numpy 대신 mulberry32), 색은 층 크기(최대 1240×1100)로 줄인 그림에서 뽑습니다. 경계가 애매한 그림에서는 묶음이 조금 다르게 나올 수 있습니다(시험 캐릭터 MOMO: 기준점 · 끝 화면 배치는 같고, 선 색이 RGB 3 차이).
- 확대 · 축소는 브라우저 캔버스(고품질)로 합니다. 같은 컴퓨터 · 같은 브라우저면 같은 그림이 나오지만, Python 판과 픽셀까지 같지는 않습니다.
- 코드 글자(2구간)는 5×7 픽셀 글꼴이라 이름 · 부위 이름의 영문 · 숫자만 나옵니다(없으면 CHAR · PART1~3).
- 형식 검사(결정론 해시 대조 · 번쩍임 · 음량 보고서)는 Python 판 `make.py finish` 에만 있습니다. 웹 판은 음악 파일(−14 LUFS)을 그대로 넣습니다.

## 확인된 것 · 확인 안 된 것
- 확인(Claude 데스크톱 앱 안 Chromium 156 · Windows): MOMO 로 16:9 · 9:16 · 4:5 굽기 → ffprobe 로 H.264 High + AAC LC · 2,400 / 1,040프레임 · 30fps · 길이 80.000 / 34.667초 · 디코드 오류 없음 · 통합 −14.0 LUFS · 트루피크 −1.9 dBTP · 음악 지연 0샘플(원본 WAV 와 상관 0.9999) · 44.2~45.3초 무음 그대로 · 영상 프레임 번호 = 장면 프레임 번호. 장면 12곳을 Python 판 스팟 프레임과 나란히 놓고 눈으로 대조. 실시간 녹화 경로(`?mode=realtime`)로 4:5 를 만들어 소리 · 그림이 들어 있음을 확인(1,040프레임 중 1,032장 기록 · 가변 프레임레이트). 저장소에 올라가는 파일만 모은 복사본을 `/color-longform-kit/` 아래 주소로 띄워(GitHub Pages 와 같은 구조) 같은 결과 확인. 실제 Pages 주소에서도 MOMO 로 16:9 · 9:16 을 구워 두 파일이 열리고 소리가 나는 것을 확인.
- 두루(`duru.png`): 색 1~3 = 황토(코트) · 빨강(목도리) · 분홍(볼 · 귀) · 진한 면 = 뿔 · 두 눈 찾음. 16:9 · 9:16 굽기 41초 → 2,400 / 1,040프레임 · 통합 −14.0 LUFS · 디코드 오류 없음. 장면 12곳을 눈으로 확인.
- 화면을 새로 짠 판(첫 화면 + 편집 화면 · 바꾸면 바로 반영 · 색 칸 → 그림의 그 자리 밝히기 · 눈 찍기 단계 · 굽는 장면 미리 보기): 두루 16:9 · 9:16(2,400 / 1,040프레임 · −14.0 LUFS · 디코드 오류 없음) · 멜론 실시간 녹화 4:5(1,040 중 2장 빠짐) · 내 그림 4:5 를 다시 구워 확인. 폭 375px 화면에서 옆으로 넘치지 않음. 굽기 모듈(mp4-muxer CDN)은 굽기 직전에 불러 와서, 그 CDN 이 늦어도 그림 넣기 · 미리 보기는 먼저 됩니다.
- 확인 안 됨: Firefox · Safari · 휴대폰 브라우저에서 굽기, 아주 큰 그림(가로 · 세로 5,000px 이상)에서의 메모리, 실시간 녹화 결과의 각 플랫폼 업로드.
- 그림이 내 캐릭터답게 보이는지는 형식 검사가 판정하지 못합니다 — 소리를 켜고 끝까지 직접 보세요.

## GitHub Pages 켜기(저장소 주인)
저장소 Settings → Pages → Source 「Deploy from a branch」 → Branch `main` · 폴더 `/ (root)` → Save. 몇 분 뒤 위 주소로 열립니다. 페이지가 `../scenes/` · `../music/` 를 읽으므로 폴더 `/web` 이 아니라 **루트**를 골라야 합니다.

로컬에서 열 때는 파일을 그대로 열면(file://) 모듈 · 그림을 못 읽습니다. 저장소 루트에서 간단한 서버를 띄우세요:
```bash
python -m http.server 8000
```
→ `http://localhost:8000/web/`
